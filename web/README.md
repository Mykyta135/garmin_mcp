# Garmin dashboard

A local Next.js dashboard over a SQLite snapshot of Garmin Connect data.

The app never talks to Garmin. `../scripts/sync.py` pulls data into
`../data/garmin.db`, and the app reads that file server-side. That keeps
Garmin's unofficial endpoints off the request path — a page load can't break
when an endpoint changes — and turns cross-metric questions into plain SQL.

## Setup

Authenticate once (writes ~6-month OAuth tokens to `~/.garminconnect`):

```bash
cd .. && ./.venv/bin/garmin-mcp-auth
```

Populate the snapshot, then run the app:

```bash
cd .. && ./.venv/bin/python scripts/sync.py    # default: last 90 days
cd web && npm run dev
```

## Syncing

```bash
./.venv/bin/python scripts/sync.py                  # fill gaps, refresh last 3 days
./.venv/bin/python scripts/sync.py --days 30
./.venv/bin/python scripts/sync.py --full           # ignore sync_log, refetch all
```

Sync is incremental and idempotent — it upserts on the date key, so re-running
is cheap. `sync_log` records which dates were fetched, *including* days Garmin
returned nothing for, so empty days aren't re-requested forever. The most
recent few days are always re-fetched, since Garmin revises them after the fact.

Read-only by construction: every Garmin call in `sync.py` is a `get_*`.

## Views

- **Readiness** — readiness score, overnight HRV, sleep stages, Body Battery vs. stress
- **Training load** — CTL/ATL/TSB, daily load, activity table
- **Correlations** — HRV against rolling 7-day load; the question Garmin Connect
  can't answer, since it shows each metric on a separate page

Charts that lack the data to mean anything render a "not enough data yet" card
instead of an empty axis. The Pearson correlation is suppressed below 14 paired
days — an *r* computed on a handful of points is noise dressed as a finding.

## Notes

- `GARMIN_DB_PATH` overrides the database location (default `../data/garmin.db`).
- The database is gitignored. It is personal health data — don't commit it.
- `better-sqlite3` is a native addon, declared in `serverExternalPackages` so
  Next requires it at runtime rather than bundling it.
- `AGENTS.md` / `CLAUDE.md` are generated by `next dev`, not hand-written.
